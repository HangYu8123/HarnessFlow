Architecture

The pack is source-controlled at this repo root, then installed into target repos under .github/harness_coding_instructions/. Tool-specific entry points classify the active user request, load shared rules, then hand off to the matching workflow family.

User request Natural language or a structured request template.
Tool router Copilot, Claude Code, or Codex discovers the entry point.
Shared context Workflow contract, safety rules, and philosophy are loaded first.
Workflow family The tool-native instruction file drives the task.
Repo memory Target-specific docs and history stay in repo_info.

Path Rules And Limits

VS Code prompts may use @/.github/harness_coding_instructions/.... CLI entry points use filesystem-relative paths such as .github/harness_coding_instructions/workflow/codex_workflow/code.instructions.md or .github/harness_coding_instructions/workflow/codex_token_effective_workflow/code.instructions.md.

Root AGENTS.md and CLAUDE.md in this source repo are templates for installed target repos. Their installed paths are expected to resolve after the pack is copied under .github/harness_coding_instructions/.
  • No runtimeThis is an instruction pack, not an application.
  • Bash scriptsSetup helpers require a shell that can run Bash.
  • Claude skillsClaude-native skill steps only apply in Claude Code environments.
  • SubagentsParallel behavior depends on the active tool and model parity support.
