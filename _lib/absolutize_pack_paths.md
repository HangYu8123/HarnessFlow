# Absolutize Claude Code & Codex Pack Paths (Canonical Procedure)

This is the single source for the absolutize step of the initialize workflows (all three families). The **calling workflow** names the step that precedes this procedure (its path-cleanup step) and the step to skip to when the idempotency guard triggers — those numbered cross-references stay in the caller; this file is step-number-neutral.

**Purpose.** After the caller's path-cleanup step, rewrite the **Claude Code** and **Codex** pack-relative path references to **absolute filesystem paths**, anchored to **this pack's own root**. This is what makes nested or multiple packs work: one repo may contain more than one pack — e.g., a parent pack at the repo root and a child pack in a subfolder, each with its own `request_template/`, `workflow/`, `repo_info/`, `_lib/`, and `philosophy/`. Paths that resolve against the working directory — pasted-in request templates, and Pack Path Resolution references such as `repo_info/…` — are ambiguous across packs; an absolute path anchored to the pack that owns the file is not.

**Scope of this rewrite:** request templates, `repo_info/` references, the always-read shared files `_lib/workflow_contract.md`, `_lib/subagent_contract.md`, and `philosophy/philosophy.instructions.md`, and the embedded request-template snapshots inside `harness_gui.html`. (Do not absolutize `agents/`, `skills/`, or narrative prose.)

**Platform rule — rewrite Claude Code and Codex forms only; leave VS Code Copilot untouched:**
- **Claude Code** forms are bare Pack-Path-Resolution paths: `workflow/…`, `repo_info/…`, `_lib/…`, `philosophy/…`.
- **Codex** forms are `.github/HarnessFlow/`-prefixed paths: `.github/HarnessFlow/workflow/…`, `.github/HarnessFlow/repo_info/…`, etc.
- Both forms → `[PACK_ROOT_ABS]/<tail>`.
- **Leave unchanged:** every VS Code Copilot `@/…` path, every `#file:…` reference, and every relative-to-file markdown-link href written as `(../…)` / `(../../…)`. Copilot keeps its native `@/[repo folder name]/` multi-root scheme from the caller's path-cleanup step; absolute paths are not part of Copilot's `@/`/`#file:` syntax, and relative-to-file hrefs are already pack-local. When a reference is a markdown link `` [`code`](href) ``, rewrite **only the backticked code-span** (which Claude Code/Codex follow) and leave the `(href)` intact.

1. **Determine `[PACK_ROOT_ABS]` — the absolute path of THIS pack's root.** It is the directory containing the `request_template/`, `workflow/`, `repo_info/`, `_lib/`, and `philosophy/` siblings being initialized — the parent of the `request_template/` directory you are editing. Resolve it from the files' own location, **not** from `git rev-parse --show-toplevel` (the git toplevel returns the outermost repo, which is wrong for a nested child pack). You already address these files by absolute path when editing them. Examples: `/Users/me/project/.github/HarnessFlow` (installed), `/Users/me/project` (source layout), `/Users/me/project/child/.github/HarnessFlow` (nested child pack).

2. **Record the root in `.pack_root` (git-ignored):** write `[PACK_ROOT_ABS]` as the single line of a `.pack_root` file at the pack root (create or overwrite), and ensure `.pack_root` is git-ignored — add a `.pack_root` line to the enclosing repo's `.gitignore` if it is not already there (create `.gitignore` if missing). `.pack_root` is the machine-local record of this pack's root: later runs, and the stale-root repair below, read it instead of re-deriving the old root from rewritten file contents. It complements — it does **not** replace — the rewrite itself: pasted request templates must carry literal absolute paths to stay unambiguous across nested packs.

3. **Idempotency guard:** if `.pack_root` exists and equals `[PACK_ROOT_ABS]`, and the in-scope Claude Code/Codex references in the files listed in step 5 already begin with `[PACK_ROOT_ABS]/`, this procedure has already run for this pack — skip to the caller's next step.

4. **Stale-root repair (moved / renamed / cloned tree):** if `.pack_root` exists but differs from `[PACK_ROOT_ABS]`, or an in-scope Claude Code/Codex reference is already absolute (begins with `/`) but under a different root — `[old_root]/{workflow|repo_info|_lib|philosophy}/…` — replace `[old_root]` with `[PACK_ROOT_ABS]` across the in-scope files, update `.pack_root` (step 2), then skip to step 6 (verify).

5. **Apply the rewrite** (substitute the real absolute path for `[PACK_ROOT_ABS]`; never leave the literal token in any file):

   **5a. Request templates** — for every `.md` under `request_template/`: each template resolves its instruction file from a dispatch table with one row per platform and one column per mode. In the **Claude Code** row, rewrite `` `workflow/{family}/{name}.instructions.md` `` → `` `[PACK_ROOT_ABS]/workflow/{family}/{name}.instructions.md` `` in every mode column, for families `token_effective_workflow`, `general_workflow`, and `skill_workflow`. In the **Codex (CLI or VS Code)** row, rewrite `` `.github/HarnessFlow/workflow/{family}/{name}.instructions.md` `` → the same absolute target. A prior install may show the `.github/HarnessFlow/…` form in the Claude Code row — map it to the same absolute target. Leave the **VS Code Copilot** row (`@/…`) unchanged.

   **5b. Root entry points** — in `CLAUDE.md` (Claude Code) rewrite the code-span references `` `_lib/workflow_contract.md` ``, `` `_lib/subagent_contract.md` ``, `` `philosophy/philosophy.instructions.md` ``, and `` `repo_info/…` `` to absolute. In `AGENTS.md` (Codex) rewrite `` `.github/HarnessFlow/_lib/workflow_contract.md` ``, `` `.github/HarnessFlow/_lib/subagent_contract.md` ``, `` `.github/HarnessFlow/philosophy/philosophy.instructions.md` ``, and `` `.github/HarnessFlow/repo_info/…` `` to absolute. Leave `copilot-instructions.md` unchanged. (This procedure runs before the caller's entry-point copy step, so the absolutized copies are what that step propagates to the repo root.)

   **5c. Shared workflow + contract files** — in every `.md` under `workflow/general_workflow/`, `workflow/token_effective_workflow/`, and `workflow/skill_workflow/`, and in `_lib/workflow_contract.md` and `_lib/subagent_contract.md`, rewrite the **backticked code-span** references to `_lib/workflow_contract.md`, `_lib/subagent_contract.md`, `philosophy/philosophy.instructions.md`, and `repo_info/…` (the bare Pack-Path-Resolution forms Claude Code/Codex follow) to absolute under `[PACK_ROOT_ABS]`. Leave every `(../…)` / `(../../…)` markdown-link href, `@/…`, and `#file:…` untouched.

   **5d. GUI embedded template snapshots** — regenerate the `<script type="application/json" id="hf-templates">` block in `harness_gui.html` (at the pack root) by running `python3 sync_gui_templates.py` from the pack root, **after 5a** — the script rebuilds the whole block byte-exactly from the (now absolutized) `request_template/*.md`, replacing it outright so no stale snapshot text survives. **Manual fallback (only if Python is unavailable):** the block embeds JSON-escaped byte-exact copies of every template, and the GUI copies these into the prompt it hands the agent (when opened via `file://` its live-sync is disabled, so the embedded copies are the only source); rewrite the Claude Code and Codex path references inside those snapshots to match the absolutized `request_template/*.md`, leave the VS Code Copilot `@/…` forms untouched, and edit only the path substrings, leaving the surrounding `\n` escapes intact.

6. **Verify:** confirm that a rewritten absolute path resolves to a real file on disk in at least one request template, one entry point, and one shared workflow file.

> **Note:** absolute paths are machine-specific. If the pack is later moved or cloned, re-run initialization — the stale-root repair (step 4) refreshes them from `.pack_root`. Avoid committing machine-local paths into shared source control (keep the rewritten files out of version control, or restore the relative form before committing; `.pack_root` itself is git-ignored per step 2).
